CONFIRMED FINDINGS

1. [P1] Comparison CLI crashes for its newly supported fallback layout.
   code/utilities/compare_models.py:133 uses undefined subject_dir instead of
   the loop variable sub_dir when segmentations/ is absent. An actual main()
   fixture with CT, both predictions and a combined gi_mask.nii.gz, but no
   segmentations directory, raises NameError before checking that combined
   mask. Root-level individual organ masks encounter the same fallback.
   Use sub_dir and cover both fallback layouts through the CLI. The helper's
   corrected physical resampling does not exercise or fix this discovery bug.

2. [P1] Clinical anatomical evaluation still ignores the synthetic reference.
   code/project10/evaluation/run_clinical_turing_test.py:83-96,189-197
   independently preprocesses the real CT using only synthetic array shape.
   The synthetic NIfTI affine is not used to establish correspondence.
   Actual function probe: an 8-cubed, 1.5-mm HU ramp with real image translated
   +1000 mm returned the identical array as the unshifted synthetic ramp;
   maximum difference was 0. A simple threshold-mask Dice was 1.0 despite
   disjoint physical support. That Dice is a synthetic geometry probe, not
   a trained-model or clinical measurement. The same correspondence problem
   remains before downstream organ comparison. Reuse the repaired synthesis
   evaluator's exact reference-grid resampling and overlap rejection here.
   Matching preprocessing recipes alone do not establish physical alignment.

3. [P1/P2] Whole-volume overlap does not validate the actual training patch.
   code/project10/datasets/multiphase_paired_dataset.py:205-217 checks target
   support over the complete NCCT. Lines 314-317 then center-crop without
   carrying that support into the returned patch. Actual dataset probe:
   a 64-cubed NCCT and edge-aligned 16x64x64 target pass with 25% global
   coverage, but the 8-cubed center patch is entirely -0.5 (normalized
   outside-image air fill), alongside valid NCCT and conditioning.
   Thus the previous disjoint-target bug is fixed, but unusable supervision
   can still reach training. Transform a target-support mask through the
   same spacing/crop, then reject insufficient patch coverage or exclude
   unsupported voxels from the loss. Do not infer coverage from HU values:
   real air and outside-image fill may have identical intensity.

4. [P2] Worker merge silently includes obsolete or unverified shard files.
   code/project10/evaluation/evaluate_synthesis.py:193-205 globs every matching
   worker CSV and ignores total_workers when selecting inputs. It neither
   checks expected shard membership/completeness nor verifies a common run
   identity or metric version before merging. Actual merge_worker_csvs probe
   with total_workers=1 and current worker_0 plus an obsolete, unversioned
   worker_7 file merged both subjects. Current L1=1 and obsolete L1=999 became
   a reported mean of 500. Stale extra shards can therefore contaminate a
   corrected cohort even though individual evaluation cache hashes improved.
   Merge only expected shards from one explicit run/manifest; require their
   completion and compatible metric/input provenance, and reject old extras
   or incomplete sets rather than silently publishing a combined cohort.

5. [P2] New compressor description still disagrees with production architecture.
   docs/SHOWCASE.md:135 now claims AutoencoderKL with a diagonal Gaussian
   posterior. Production use_vq=False returns LightweightAutoEncoder3D from
   code/project10/models/autoencoder_3d.py:261-266. Its encode() directly
   returns encoder features; forward() supplies zero auxiliary loss in this
   mode. There is no posterior mean/log-variance, latent posterior sampling
   or KL regularization on this path. Describe the current model as a
   deterministic continuous 3D autoencoder; do not replace VQ-VAE with another
   unsupported architecture label. This finding follows the current source
   contract, not a claim about an unavailable historical checkpoint.
