REMAINING IMPLEMENTATION FINDINGS

1. [P1] JHU physical-coordinate evaluation is still demonstrably wrong.
   evaluate_jhu_radiologist_gpu.py:315-316 accepts equal size/direction without
   checking origin or spacing;326-340 replaces valid source geometry with
   invented spacing/origin/direction for other orientations. Fresh runs of the
   actual evaluator on temporary images reproduce both counterexamples:
   -Masks1000mm apart: physically correct Dice0.0, evaluator Dice1.0.
   -Same physical mask in opposite X direction: correct Dice1.0, evaluator0.0.
   The new CPU wrapper delegates to this implementation, so both routes share
   the defect. Always resample from actual source geometry onto the reference;
   do not infer source metadata from ground-truth array dimensions.

2. [P1] Phase3 evaluation can select uncertainty instead of segmentation.
   evaluate_jhu_radiologist_gpu.py:279-286 selects the first broad filename
   match. Consensus preference289-293 applies only to exact EnsembleConsensus,
   not EnsembleConsensus_Phase3 used by run_jhu_eval_community.sbatch:43.
   An actual-evaluator probe selected CASE_uncertainty.nii.gz and reported
   stomach Dice0 despite a correct CASE_consensus.nii.gz in the same directory.
   Use exact model-specific segmentation filename patterns, reject ambiguity,
   and explicitly exclude uncertainty/probability/CT artifacts.

3. [P1] Physical showcase alignment is fixed only in the comparison branch.
   generate_showcase.py:597-600 still accepts equal-shaped masks or shape-zooms
   them for volumes, HU statistics, meshes, orthoviews, and export. Line700
   stamps CT geometry onto that array. An actual process_subject probe with a
   mask shifted1000mm exported216 foreground voxels at the CT origin; physical
   resampling correctly gives zero. Reuse one physically aligned label object
   throughout all measurements, images, and exports. The corrected comparison
   renderer should not be the only path that establishes coordinate alignment.

4. [P1] Explicit TotalSegmentator v1 selection can be overridden by content.
   sample_multiphase_diffusion.py:218 tests presence of18/19/20 before honoring
   total_v1 at224. Valid v1 full-body masks contain those IDs for other anatomy.
   Exact loader probe with511 voxels of v1 duodenum56 and one voxel18, explicitly
   passing total_v1, returned511 background voxels and one small-bowel voxel;
   expected511 duodenum voxels and one background voxel. Explicit schema must
   select the mapping before any optional auto-detection. Label presence cannot
   independently establish producer version, especially after cropping.

5. [P1] Clinical agreement uses the wrong crop for the corrected sampler.
   Sampling and evaluate_synthesis now center-crop, but
   run_clinical_turing_test.py:109-117 still takes the low-index corner.
   Fresh20-cubed to8-cubed ramp probe:
   -Sampler/synthesis evaluator xHU:60,70,80,90,100,110,120,130.
   -Clinical evaluator xHU:0,10,20,30,40,50,60,70.
   Thus the agreement endpoint compares different anatomical patches. Share
   the source-grid/crop transform across every evaluator and figure generator.

6. [P2] Merely center-cropping does not fully unify preprocessing.
   Training/figures use MONAI Spacingd then ResizeWithPadOrCropd; sampling uses
   SimpleITK size=round(size*spacing/1.5). Those resampling extents differ for
   some grids. Fresh20-cubed1mm input to8-cubed output:
   -Sampler xHU:30,45,60,75,90,105,120,135.
   -Training transform xHU:45,60,75,90,105,120,135,150.
   Use a shared physical reference grid and crop transform, rather than
   independently rounded implementations. The previous1.5mm ramp case is
   fixed, but passing that case is not sufficient for native acquisition grids.

7. [P1] Stage2 launch still defaults full-body masks to the GI schema.
   run_p10_stage2_synth.sbatch:68 uses results/totalseg_masks without an explicit
   task, while trainer:280/dataset:65 default to gi. Dataset225-228 retains raw
   labels1..4 as stomach/duodenum/bowel/colon, although those IDs have different
   meanings in total masks. Set the producer schema in launchers and verify it
   against source metadata before training or resuming.

8. [P1] Inference does not enforce checkpoint AE/conditioning compatibility.
   train_stage2_synthesis.py:174-199 validates ae_checkpoint_sha256 and
   conditioning identity during resume. Sampling:300-333 instead loads the
   supplied AE and diffusion weights independently without comparing these
   fields. Same-shaped but different AE weights or mask semantics can load
   successfully while changing the latent coordinate system. Reuse audited
   identity checks at inference and record the resolved input/AE/mask contract.

9. [P1/P2] Missing mask discovery still silently removes conditioning.
   sample_multiphase_diffusion.py:178-180 only discovers subject.nii(.gz).
   Training accepts subject_gi_mask.nii.gz and subject_mask.nii.gz as well.
   A fresh supported-suffix probe returned a512-voxel all-background prior,
   with the actual mask ignored. Missing/unreadable masks return neutral
   background at241-244. Share training discovery, validate foreground and
   schema, and fail or explicitly label genuinely unconditioned generation.

10. [P1] Detection flags remain detached from acceptance.
    Clinical evaluator:235-241 and stress evaluator:331-336 record>50-voxel
    flags but include every non-NaN organ Dice in the score. One coincident
    organ voxel can yield mean1.0 even when all coverage flags are false.
    Both-empty NaN gating is correct but does not establish adequate organ
    coverage. Define minimum eligible support and publish eligible denominators.

11. [P2] Physical output and tumor-host provenance remain incomplete.
    Sampler:413-414 writes a zero-origin diagonal affine, losing patient
    geometry/crop translation. Tumor masks are independently resampled using
    their own origin and corner extent at generate_multiphase_tumors.py:63-72.
    Equal array shapes cannot prove host containment in the generated patch.
    The tumor helper now takes an explicit task, but main:231 does not pass it
    and the CLI does not expose it. v1 production input therefore uses the
    default v2 semantics. Binary host masks still lack organ identity checks.

12. [P2] Patient-independent evaluation is not established.
    train_stage2_synthesis.py:364-369 random-splits pair rows, ignoring
    patient_id; repeated phases can cross train/validation. Production overlap
    requires the unavailable manifest to quantify. Table compilation:154 still
    counts unique scan subject_id values as patients; the new50-row table
    repeats11 scans as11 patients despite known phase reuse. Use real patient
    grouping for split, aggregation, sample counts, and uncertainty estimates.

13. [P2] Partial sampling failures can still return a successful worker status.
    Lines424-425 raise only if every sample failed. Existing output files are
    counted as success at348 without checking readability or run identity.
    One stale output can therefore mask failure of all fresh samples. Report
    attempted/generated/skipped/failed counts separately, validate skipped
    artifacts, and make incomplete-run status visible to downstream workflows.
