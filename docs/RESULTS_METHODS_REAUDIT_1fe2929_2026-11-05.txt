CONFIRMED REMAINING FINDING

1. [P2] The verifier rejects supported explicitly named evaluation runs.
   evaluate_synthesis.py:729-732 documents --run_id as a supported option and says
   deterministic identity is generated when it is omitted. At :817-819, the actual
   evaluator replaces manifest run_id with that explicit user-provided label.
   In contrast, verify_production_results.py:726-736 now unconditionally requires
   both CSV and manifest run_id to equal the computed cohort snapshot digest.
   The producer and verifier disagree about the identity contract.

   Actual reproduction using otherwise valid temporary data and completion proof:
   - The default deterministic-ID evaluator output passes lineage verification.
   - Actual evaluator execution with --run_id audit_named_positive_control succeeds.
   - Actual strict merge with expected_run_id=audit_named_positive_control succeeds.
   - Production lineage verification rejects this result. Its computed digest is
     run_314a03a5f4533a55, while the supported producer label is
     audit_named_positive_control. Hashes, subjects and completion remain valid.

   This is a demonstrated false rejection of a valid supported evaluator output,
   not evidence that current default production results are incorrect.
   Required repair: align the producer/verifier contract. Preserve a separately
   authenticated content/snapshot identity alongside the user run label, or
   explicitly change/document supported producer behavior consistently. Retain
   mandatory row/file hashes, assignment and completion checks; do not restore
   run-name-only authentication. Test both automatic and explicit labels through
   actual evaluation, strict merge and verification, including an idle worker.
