Scope: source and lightweight standard-library AST inspection only; no project imports, training, full tests, cluster jobs or source edits. No measured model performance is inferred.

F1 [P1] Synthetic labels are taken from unrelated real training rows, and missing synthetic features are silently replaced by arbitrary Gaussian jitter.
Source: benchmark_lesion_augmentation_utility.py:302-317.
Both augmentation arms read synthetic feature rows but set y_syn=y_train_real, without joining or deriving the synthetic lesion pathology label. Reordering the synthetic manifest changes feature/label associations; a benign synthetic lesion can receive the label of an unrelated malignant real lesion. Synthetic rows are not filtered to hepatic pathologies. When synthetic feature columns are absent, no synthetic lesion is used: X_train_real+Normal(0,5) orNormal(0,8) is substituted. The advertised incremental perfusion comparison therefore becomes an arbitrary jitter-scale comparison, not a test of the procedural generator. If an arm has fewer synthetic rows than real training lesions, X andy lengths also differ because feature truncation does not cap y_syn to the actual sampled synthetic count.
Acceptance: require valid typed features and labels on every admitted synthetic lesion, derive y_syn from its own reference pathology, and join arm2/arm3 by matched parent/geometry/pathology IDs. Missing required synthetic features must fail explicitly, not become invented observations. Gate arm sizes and label alignment before fitting.

F2 [P1] Untouched real test patients are not protected from synthetic-parent/generator exposure.
Source: benchmark_lesion_augmentation_utility.py:255-275,304-317.
The real train/test split is patient-disjoint, which is an improvement. The entire preexisting synthetic manifest is then eligible for both augmentation arms; there is no source/parent patient exclusion, generator development membership check, split assignment join, or provenance linking synthetic records to train patients only. A synthetic lesion/background originating from a real test patient can therefore be used in training. Patient-cluster bootstrap cannot repair training/test leakage.
Acceptance: lock real patient/center splits before generation; require synthetic source/parent IDs and generator-training membership; reject any held-out patient exposure in each arm. Persist actual patient/lesion IDs and generator checkpoint lineage rather than asserting untouched-real evaluation from the real CSV split alone.

F3 [P2] The claimed matched three-arm intervention is not implemented.
Source: benchmark_lesion_augmentation_utility.py:12-20,296-317.
Arm1 fits N real training rows; arms2/3 fit N real plus up toN synthetic rows. Same RandomForest(n_estimators=100,max_depth=6) does not give equal cases/exposure or an identical optimizer-update budget. No standard spatial/intensity augmentation is applied to arm1. Arm2/arm3 independently filter manifest rows; no matching of geometry, parent background, pathology mix or synthetic dose isolates kinetics as the only varying intervention. n_estimators is a forest-size parameter, not an optimizer-step count. Regional-feature random-forest analysis can be a useful feasibility study, but the claimed3D/4D matched-optimizer protocol and causal kinetics benefit do not follow from this implementation.
Acceptance: define an implementable feature-classifier or volumetric-classifier protocol explicitly. Match real data exposure and synthetic count, pair synthetic instances across arms, prespecify feature extraction/preprocessing and sampling, and report the actual arm counts/training budgets. Test incremental kinetics with all other generator factors held constant. Report results only from completed real holdout predictions and paired patient-level inference; no such study is demonstrated merely by this code.

F4 [P1] New registration QA output breaks the Stage2 dataset's producer-consumer contract.
Source: register_multiphase_pairs.py:380-387,436-449,459-480; multiphase_paired_dataset.py:91-104.
The producer now writes15 columns and marks accepted cases PROVISIONAL_PASS_QA_SCREEN. The dataset still reads the former9-field schema with header=None and retains only status=='OK'. Thus new accepted rows are either misparsed or rejected; the new QA-screened target cohort is not admitted to diffusion training. AST inspection confirms15 producer fields versus9 consumer fields. If a previous9-column log is appended without a versioned migration, mixed-format rows are additionally produced.
Acceptance: version and read named columns, preserve explicit provisional versus independently approved status semantics, add an end-to-end producer->dataset contract check, and fail nonzero when no eligible training data remain. Do not relabel provisional QA as independent anatomical approval.

F5 [P2] Date equality is promoted to verified session identity even when accession evidence conflicts.
Source: discover_multiphase_cohort.py:208-233.
Accession matching is correctly prioritized and the earlier most-recent-only source bug is improved. But if target accession has no source match, same-date fallback sets session_matched=True, later labeling verified_same_session. This includes two known, different accession numbers on the same calendar date; the more informative evidence of different examinations is discarded. The no-date fallback is described as closest-date but actually picks the most recentNCCT (:224-226), not the closest date.
Acceptance: distinguish verified same accession/session, same-date-only, longitudinal and unknown. Do not promote conflicting accessions based on date equality. Use actual session IDs for the primary matched study and retain same-day-only cases as a sensitivity cohort. If closest-date pairing is desired, compute absolute time difference with a prespecified allowable interval.

F6 [P2] The real feature-availability fallback cannot populate the already copied train/test frames.
Source: benchmark_lesion_augmentation_utility.py:274-289,291-294.
train_df/test_df are .copy() subsets before the fallback adds missing mean_hu/std_hu/volume_voxels columns to real_df. With a manifest containing only the required patient_id/lesion_id/pathology fields, availability passes but subsequent train_df[feature_cols] indexes columns never added to train_df and raisesKeyError. More generally, placeholder constant features must not be treated as verified image measurements.
Acceptance: require a locked nonempty numeric feature schema and provenance, or perform actual CT feature extraction with explicit failure handling before splitting. Reject unavailable features as DATA_UNAVAILABLE/INVALID_INPUT rather than substituting constants or jitter.

Additional design limitations: the split is a random patient shuffle, not the patient-class-stratified split claimed in the comment (:266-272); the minimum input check counts10rows rather than independent patients/per-class patients, and no post-hepatic-filter train/test class gates exist before fit/predict_proba/AUC. One-class or empty splits can fail or produce undefined inference. Only one seed is run, so patient bootstrap conditions on one fitted realization rather than measuring between-training variability. These are limits to prespecify and address before interpreting benefit.

Verified source-level improvements: fixed invented AUC/significance constants are removed; missing input files now emit DATA_UNAVAILABLE and exit2; actualRandomForest fitting and held-out real predictions are wired; statistics compare arm3versusarm2 using patient-cluster resampling/permutation rather than assuming significance. Registration now distinguishes rigid_xfm versusaffine_xfm outputs and persists Jacobian QA fields; topology failures are separated from provisional passes. These are implemented components, not completed empirical validation, and the producer-consumer issue above currently blocks their training integration.
