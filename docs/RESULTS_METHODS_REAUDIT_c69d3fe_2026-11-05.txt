CONFIRMED REMAINING VERIFIER FINDINGS

1. [P1] Authentication can be skipped and is disconnected from metric/support rows.
   code/evaluation/verify_production_results.py:648-670 checks a hash only when the
   manifest supplies its filename and hash AND the candidate file exists. Missing
   hashes and missing files leave hashes_valid=True. The block does not join CSV
   input hashes to the manifest, nor authenticate support masks against current
   data. These are not strict mandatory input checks.
   Actual accepted counterexamples, starting from real two-case evaluator output:
   - Remove manifest fake/real hashes, then change a finite registered CT.
   - Point fake_dir/real_dir to nonexistent paths and supply bogus hashes.
   - Replace metric-row fake/real/support hashes with contradictory values.
   - Change a support mask while retaining recorded metrics and hashes.
   All return cohort_lineage_ok=True. In contrast, a present recorded real hash
   mismatch at an existing path now correctly rejects.
   Required repair: require every path/hash/row identity, reject missing files,
   bind each scored row to the manifest/current fake/reference/support payloads,
   and authenticate model/checkpoint/config identity where required by the claim.

2. [P1] Completion proof remains optional; alternative worker identity is incomplete.
   At verify_production_results.py:672-675 a hash-valid discovery manifest alone
   sets run_verified=True. Deleting all completion sidecars still passes the
   actual evaluator-to-verifier positive control. Cohort discovery and matching
   volume identities do not demonstrate completed successful metric execution.
   The fallback at :695-728 compares distinct worker count with total_workers,
   but not the actual set 0..N-1 or consistent totals across sidecars. Counts may
   substitute for subject lists. Actual lineage PASS occurs for worker 99 of 1,
   and workers 5/6 whose declarations say total_workers 2/999.
   Required repair: require complete, consistent execution metadata as well as the
   manifest, verify exact worker IDs/ownership and subject assignments, and check
   completion, errors, counts and row provenance together. Reuse the evaluator's
   strict merge contract rather than a weaker independent approximation.

3. [P2] A finite/readable DVF can have the wrong physical grid or vector dimensions.
   verify_production_results.py:541-544 only checks len(shape)>=4 and whether any
   trailing dimension equals 3. It never compares DVF spatial shape/affine with
   the corresponding registered volume or expected reference grid.
   With otherwise accepted real evaluator output, changing only the DVF affine
   by 100 mm still yields lineage PASS. A DVF shaped (16,16,16,2,3), with an
   invalid extra non-singleton axis, also passes. CRC and finite values remain
   valid in both probes, isolating geometry/vector-layout validation.
   The registration producer explicitly uses the fixed reference image for its
   displacement field (register_multiphase_pairs.py:258-260) and writes registered
   CT/support on that grid (:300-315). The verifier does not establish this
   producer contract. These probes do not establish registration accuracy.
   Required repair: validate an allowed vector layout (XYZ,3 or XYZ,1,3), exactly
   three components, finite displacements, and spatial geometry/reference identity
   for every matched CT/DVF/support set.

SECONDARY MODEL CONFIGURATION FINDINGS

4. [P3] Cache reuse omits constructor inputs.
   eval_scaling_checkpoints.py:527 omits in_channels and model_id from model_key.
   Two UNet declarations with one versus two input channels collide. Both real
   models load their matching states independently, but reuse of the one-channel
   model for the two-channel checkpoint raises parameter-shape mismatches.
   This is a general multi-checkpoint API gap; the current single-channel CT path
   was not demonstrated to fail. Key reuse on complete validated configuration.

5. [P3] Contradictory local/legacy configuration is accepted.
   eval_scaling_checkpoints.py:347-349 ignores declared local variant/kernel;
   :383-387 selects local B whenever a legacy MedNeXt declaration has kernel 7.
   Actual declarations for local MedNeXt-S/kernel 3 and legacy MedNeXt-S/kernel 7
   both construct local B/kernel 7. Correctly emitted local-B metadata works.
   Reject contradictory declarations and avoid inferring factory from kernel size
   alone when variant/factory identity is ambiguous. The previously reported
   explicit-factory precedence and unknown-factory fallback bugs are closed.
