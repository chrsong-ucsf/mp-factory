REMAINING FINDINGS

1. [P2] Default trainer manifests do not match their evaluation consumer.
   Phase1/2 trainers default to fold=-1 and write fold_-1_manifest.json (e.g.
   train_mednext.py:390; train_mednext_phase2.py:552). New
   eval_scaling_checkpoints.py:185-193 recognizes only fold_(digits), then expects
   train_manifest.json when no nonnegative fold is found. Actual helper probe with
   a valid default-fold manifest rejects it as missing. Support producer filenames
   and negative/default folds explicitly; test trainer-to-evaluator handoff.

2. [P2] Manifest schema validation still does not authenticate checkpoint membership.
   eval_scaling_checkpoints.py:208-232 validates a nonempty membership list and an
   optional matching fold. It requires no content hash, architecture/configuration
   identity, split/data fingerprint or nonblank member IDs.
   Actual probes accept {train_cases:[CV_1000_P0]} without hashes/configuration;
   replacing checkpoint contents leaves acceptance unchanged; train_cases:[space]
   also passes and is later stripped, excluding nobody.
   Bind membership to the saved checkpoint and executed configuration; reject
   blank/malformed identifiers. File adjacency and matching model keys do not prove
   which patients trained a same-architecture model, including legacy warm starts.

3. [P2] Actual training size is not propagated through every scaling artifact.
   New folder and train manifest correctly use measured N at
   run_scaling_sweep.py:659,665-669. Epoch rows/checkpoints/epoch JSON still use
   requested n_cases at:795,825,830. write_sweep_summary():862 groups that value;
   progress CSV:1125 still writes requested N.
   Actual one-epoch probe: request2/train1; folderN0001 and manifestn_train_scans1,
   but epoch JSONn_cases2 and generated sweep summaryn_cases2. The fitting helper
   now prefers n_train_scans when present, but its producers/other consumers must
   supply it consistently. Propagate requested/actual scan/patient counts through
   checkpoints, epochs, summaries and progress records; label the fitted quantity.

4. [P2] Full-payload verification still only reads headers.
   verify_production_results.py:459-504 visits every registration/synthesis/DVF
   filename but obtains nib.load(...).header without reading voxel payloads.
   Actual scanner accepts a matching synthetic gzip truncated to2000bytes: header
   loads as16-cube, get_fdata() raises EOFError, cohort_lineage_ok remainsTrue.
   Read and validate every required payload and finiteness/vector semantics, or
   accurately label the check as header inventory rather than complete readability.
   The previous unsampled-corrupt-header case is fixed by all-header traversal;
   this is a separate compressed-payload truncation defect.

5. [P1/P2] Verification accepts unproven run identity and mixed metric contracts.
