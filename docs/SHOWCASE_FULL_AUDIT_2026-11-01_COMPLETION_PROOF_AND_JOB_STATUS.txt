CONFIRMED FINDINGS

1. [P2] Merge still succeeds without proving cohort completion.
   code/project10/evaluation/evaluate_synthesis.py:332-343 loads a manifest
   only if present. Worker completion metadata at 351-356 onward is also
   optional. Without those files, strict/default merge has no expected cohort
   or completion proof, yet can publish a result without allow_partial=True.
   In addition, the all-empty return at 443-446 occurs before manifest coverage
   checks at 475 onward and before input-directory/hash validation.

   Actual counterexamples:
   - A genuine two-case evaluation failed after scoring only A. Its original
     failed-worker metadata correctly blocked merge. Copying only that CSV
     into a reporting directory, without manifest/metadata, allowed default
     merge to publish A as the cohort. No CSV rows were fabricated or edited.
   - A schema-only worker CSV plus a manifest expecting A published zero rows
     successfully, even with inaccessible input directories. Independent and
     primary-reviewer probes reproduced this. The primary probe also supplied
     completed/zero-assignment metadata: the contradiction with the nonempty
     manifest was still bypassed by the early return.

   Require valid manifest and worker completion evidence for verified/default
   merging, including transferred reports. Validate expected subjects and
   assignments before returning an empty result. Keep any explicitly requested
   unverified/partial export separate and visibly identified. A missing proof
   file or empty CSV must not turn an incomplete cohort into a verified result.

2. [P2] The evaluation SLURM launcher masks Python worker failures.
   code/slurm_scripts/run_p10_evaluate_synthesis.sbatch:32-41 invokes the
   evaluator and then prints completion messages, without set -e, exec or
   explicit status propagation. The final successful echo determines the
   shell's exit code even if the evaluator returned nonzero.
   Actual unchanged-script probe, with module/mamba/mkdir/python commands
   replaced through temporary BASH_ENV shell functions: evaluator stub returned
   7; launcher printed 'completed evaluation' and exited 0. Independent and
   primary-reviewer probes agreed. No HPC paths were written and no jobs ran.
   This is a pre-existing uncovered launcher defect, not introduced by d296f5b.
   Propagate evaluator failure and only print completion after success. Verify
   failure and success exit behavior, so SLURM/job dependencies can distinguish
   a failed evaluation from a completed worker.
