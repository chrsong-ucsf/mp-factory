CONFIRMED FINDINGS

1. [P1/P2] Partially unsupported targets still enter training as real air.
   code/project10/datasets/multiphase_paired_dataset.py:329-339 accepts target
   patches with >=10% support and returns target_support. But production
   training at training/train_stage2_synthesis.py:459-480 and validation at
   503-517 never consume that mask: the full filled target is encoded, and
   all latent voxels enter MSE.
   Actual dataset probe: 64-cubed NCCT, edge-aligned 32x64x64 target, and
   8-cubed center patch were accepted with target_support mean 0.5. The
   unsupported half of target was entirely -0.5 normalized fill air.
   Zero-support rejection is now correct, but partial support still supplies
   fabricated supervision. Reject inadequately supported patches, or propagate
   support into latent supervision with appropriate encoder receptive-field
   treatment. Merely returning a support mask does not change the loss.

2. [P2] Voxel evaluation scores missing reference data as measured -1000 HU.
   code/project10/evaluation/evaluate_synthesis.py:59-109 accepts references
   covering >=10% of the generated grid and fills the rest with -1000 HU.
   compute_metrics_3d at 112-166 and the caller at 410-413 score that filled
   array without a reference-support mask. Uncovered space is missing data,
   not an observed air measurement.
   Actual unmocked probe: two constant 100-HU 8-cubed volumes at 1.5-mm spacing,
   with the real reference shifted 6 mm, have 50% coverage. Supported-voxel
   L1 was 0, but whole-volume reported L1 was 550 HU because the other half
   became -1000 HU. Thus source coverage changes a supposedly paired image
   error even where all observed voxels agree.
   Either require sufficient complete reference support for the reported
   endpoint, or return/propagate support and compute appropriately defined
   metrics only on comparable observed regions. Structural metrics need a
   valid-window policy, not just multiplying missing voxels by zero. Report
   coverage and do not infer support from intensity values.

3. [P2] Merge silently chooses an arbitrary row from conflicting runs.
   evaluate_synthesis.py:227-244 checks expected worker indices and metric
   version, then drops duplicate Subject rows keeping the first. There is
   no common run/assignment/input manifest or conflict check.
   Two independent actual merge_worker_csvs probes supplied valid-version
   expected worker_0 and worker_1 records for the same subject with different
   real/fake hashes. Worker 0's stale L1=999 survived; worker 1's L1=1 was
   discarded without an error. Both worker files passed the new checks.
   Require a shared run identity/assignment and completion manifest, validate
   input hashes, and reject conflicting duplicates. Matching the metric
   implementation version does not prove two shards belong to the same run.

4. [P2] Successful idle workers do not produce the shards merge now requires.
   evaluate_synthesis.py:444-448 returns without writing a CSV when a worker
   has no assigned cases. Merge at 204-215 requires every index from zero
   through total_workers-1 to have a CSV.
   Actual unmocked one-case/two-worker run: worker 0 scored its case, worker 1
   had zero assigned cases and returned successfully; only worker_0.csv
   existed. The subsequent merge raised RuntimeError for missing worker_1.
   Emit schema-bearing empty shards plus completion metadata, or derive
   expected nonempty shards from an explicit assignment manifest. Preserve
   detection of genuinely failed/missing workers while allowing legitimate
   zero-case assignments. A small smoke cohort should remain mergeable.
