CONFIRMED FINDINGS

1. [P2] Generated run ID does not identify the input snapshot.
   code/project10/evaluation/evaluate_synthesis.py:454-455 hashes directory
   paths, metric version, file names and count. It omits actual input contents
   and worker assignment. The merge route trusts the resulting ID without
   rechecking every row against a frozen input manifest or current files.
   Actual two-worker probe: both cases initially scored L1=1. Changing case B's
   real reference from 101 to 103 HU and rerunning only worker 0 retained the
   same generated run ID. Merge accepted worker 1's old B score of 1, although
   the current input requires 3. The single-worker resume hash checks do not
   help a worker that was never rerun.
   Generate an immutable input/assignment manifest whose identity includes
   relevant content hashes, and bind every shard/completion record to it;
   alternatively revalidate all merged rows against current inputs. A stable
   directory/list identity is not an immutable measurement snapshot.

2. [P2] Required run provenance still permits blank IDs on individual rows.
   evaluate_synthesis.py:279-285 checks only that the run_id column exists.
   Line 300 then calls dropna().unique(), allowing unidentified rows to vanish
   from the consistency check when another row supplies one valid ID.
   Actual expected-shard probe: case A with run_id='known' and case B with a
   blank ID merged successfully. Independent and primary-reviewer probes
   reproduced this; explicitly passing expected_run_id='known' still accepted
   the blank case B row.
   Require a nonempty, non-whitespace identity for every data record and
   validate that all records match the expected run. Validate zero-row worker
   identity/completion through separate metadata rather than ignoring missing
   values. A column heading alone does not establish each row's provenance.

3. [P2] Clinical Dice still scores missing reference coverage as background.
   code/project10/evaluation/run_clinical_turing_test.py:186 requests aligned
   real CT without return_support. The shared resampler permits partial
   coverage and fills uncovered regions with -1000 HU. Full-array organ Dice
   at 203-214 then compares those unobserved regions as if they were measured
   reference background.
   Actual clinical main() probe: constant 100-HU inputs with 50% physical
   reference overlap have perfect agreement over observed voxels. Using a
   threshold segmenter/model substitute, the real resampling, scoring and
   pass/fail flow reported stomach Dice 0.6667 and failed its 0.70 threshold,
   because the missing half became background. This is a synthetic scoring
   counterexample, not trained-model inference or a clinical result.
   Require complete reference coverage for this endpoint, or propagate valid
   support into the clinical comparison while accounting for the segmenter's
   inference context. Record coverage and exclude unavailable evidence instead
   of treating fill air as observed anatomy. Voxel metric support fixes do not
   automatically protect this separate downstream evaluation path.
